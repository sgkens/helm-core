## Dense vertical gauges: layout guidance

Request: warn about text overlap on small displays and dense vertical grids, and explain how to enlarge panels instead of shrinking text until unreadable.

[Gauge documentation](../docs/content/gauges.md#small-displays-and-dense-vertical-layouts) now explains that values and labels need space above and below vertical gauges. Use short labels, fewer columns and `at(col, row, spanX, spanY)` to give panels more grid cells. The request's `w{2}` shorthand is not supported DSL; no new shorthand was added. Explicit panel font overrides bypass the profile scaling.

The example uses two vertical gauges in one panel spanning a 2×2 grid. It is checked by the real parser through the documentation frame build. The [#6 font reduction](issue-006-corner-lcd-text.md) remains the shared core fix; guidance does not promise that arbitrary dense layouts will fit.

## Themed animated power gauges

Request: component-specific animated designs for reactors, batteries, solar panels and hydrogen engines using the existing liquid animation and gradients.

Added [`power_liquid_themes.txt`](../layouts/default/power_liquid_themes.txt) to the shared preset library, automatically included in the docs gallery and Toolbox. It has four independent screens with amber reactor, green battery, yellow solar and violet engine gradients. It uses the existing `tank(...)` gauge and `profile: auto`; no new gauge kind or theme directive is required. Rename the groups and LCD targets to match the grid.

| Theme | Value | Meaning |
| --- | --- | --- |
| Reactor | `reactor.percent` | Current output / maximum output |
| Battery | `battery.percent` | Stored charge / capacity |
| Solar | `solar.percent` | Current output / maximum output |
| Hydrogen engine | `engine.percent` | Current output / maximum output |

These are not fuel or temperature sensors. Group values use the existing average aggregation. Waves follow time; fill follows telemetry. Toolbox Play does not vary the sliders automatically.

The audit found that hydrogen engines fell through to the enabled-status percentage instead of power output. Added an `IMyPowerProducer` fallback after the existing battery/reactor/solar/wind branches, preserving battery charge semantics. Runtime checks cover half output, enabled-but-idle, full output and zero capacity. Existing interfaces are reused; no shim API changes were needed.

The final script is **98,023 characters**, leaving **1,977** under the 100,000 limit. The clock-based spinner costs 5 characters over the prior local patch; the power-producer correction adds 108. The four themes and layout guidance add zero PB characters because they are Custom Data and documentation. Runtime work uses existing liquid sprites; the new fallback adds a type check for blocks that reach that branch. No in-game performance benchmark was run.
